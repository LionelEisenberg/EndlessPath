# Merchant v1 Implementation Plan

> **Status (2026-10-19):** Tasks 1–6 done inline (superpowers:executing-plans); 4 new test files, full suite 581/581. Deviations, each recorded as a ruling during execution: Task 3 tests check rules (positive prices, the spec's items, the ledger key) instead of exact prices and counts; no `RowMargin` node; `MerchantAtmosphere` clips itself; `MerchantButton` has no glow shadow; the Spirit Valley action sets `shop_theme` explicitly; `MerchantViewState`'s "pops only itself" guard is checked in play, not by a test. Nothing is committed until the user reviews the diff.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Traveling Merchant stub into a shop where adventure gold buys six gear pieces and Crude Scales, with gear sold out once per save.

**Architecture:** A `MerchantManager` autoload owns the purchase rules and one ledger per merchant in `SaveGameData.merchant_ledgers`. `ActionManager` opens and closes the shop with `start_merchant` / `stop_merchant` signals. A `MerchantViewState` overlay shows a scene-tree `MerchantView` whose pre-instanced rows only display data.

**Tech Stack:** Godot 4.6, GDScript, GUT 9.6.0.

**Spec:** [docs/superpowers/specs/2026-10-19-merchant-v1-design.md](../specs/2026-10-19-merchant-v1-design.md) (Claude doc copy for review: https://claude.ai/code/artifact/3c8c0d3c-bd8b-4dd2-bc64-fedbaff8d64d)

## Global Constraints

- GDScript standards from CLAUDE.md: explicit return types, typed class variables, `##` docs on public functions and classes, `_` prefix for private functions, `%UniqueName` node references, `#---` section headers, no `print()`.
- No UI node is created in code. Every node lives in a `.tscn`; text uses Label theme variants from `docs/UI_STYLING.md`; scripts set only text, visibility, textures, disabled state, data, the view's `theme` (a Theme resource from data) and `modulate` from theme colours. No `add_theme_*_override()` in scripts.
- Reusable scenes are referenced with `instance=` in the parent `.tscn`, never `preload().instantiate()` in scripts.
- Never modify `addons/`.
- Stay out of: encounter `.tres`, loot tables, `CombatConsumableManager`, the combatant info panel, `VitalsManager`, `adventure_view`, path-tree and combat-ability files.
- Prices (starting values, in item `base_value`): Crude Scale 10, Cultivator's Cowl 40, Makeshift Dagger 60, Scripted Bark 75, Leeching Ring 120, Iron Shortsword 150, Reinforced Robes 180.
- Stock limits: every gear entry `stock_limit = 1` (once per save from that merchant, still sold out after trashing); Crude Scale `stock_limit = 0` (unlimited). Limits are tracked per merchant: ledger key `MerchantStock.merchant_id`, entry key `MerchantStockEntry.entry_id`.
- Copy: row reasons "Need N more gold" and "Equipment full"; sold-out label "Sold out"; footer after a purchase "Bought <item name>."; button "Buy"; leave button "Leave [Esc]".
- No commits per task. CLAUDE.md requires the user to review the whole diff before any commit; Task 7 proposes the commit split.

## Review Focus

1. An old `save.tres` without `merchant_ledgers` must load with an empty dictionary, so nothing shows as sold out. Test in Task 1.
2. A second Buy click on a `stock_limit = 1` entry must return `SOLD_OUT` and charge gold once. Test in Task 2.
3. Gold changed while the shop is open (dev panel `set_gold`) must refresh every row's affordability. Test in Task 5.
4. A second `stop_action()` (Escape pressed again during the fade-out) must not emit `stop_merchant` twice, and `MerchantViewState` must pop only itself. Test in Task 4.
5. A stock list longer than the 8 pre-built rows must show the first 8 and log a warning, not crash. Test in Task 5.

- Produces: `enum PurchaseResult { OK, INVALID_ENTRY, SOLD_OUT, INSUFFICIENT_GOLD, EQUIPMENT_FULL }`; `signal item_purchased(stock: MerchantStock, entry: MerchantStockEntry)`; `get_purchase_status(stock: MerchantStock, entry: MerchantStockEntry) -> PurchaseResult`; `purchase(stock: MerchantStock, entry: MerchantStockEntry) -> PurchaseResult`; `get_purchase_count(stock: MerchantStock, entry: MerchantStockEntry) -> int`; `get_remaining_stock(stock: MerchantStock, entry: MerchantStockEntry) -> int` (-1 when unlimited); `get_gold_shortfall(entry: MerchantStockEntry) -> int` (0 when affordable).
